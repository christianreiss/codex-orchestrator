# Bugs

Read-only audit of the orchestrator server and `cxx` (`cdx`, `clx`, `cgx`) on 2026-10-11. No services were started, no processes were killed, and no live client was shut down. Shutdown and kill behavior below is what the code does.

The per-engine pass covered 19 features on Codex, Claude, and Grok, then six extras: Git Director, projects, secrets, transfers, the Android companion, and host provisioning. Clean feature/engine pairs are listed at the end. Seventy-five audits ran. Secrets was clean on all three engines. Companion was clean on Claude.

Sandra holds this checkout for a deploy. This file is the only write.

## Inventory

Server surfaces that participate in a client lifecycle: host register and install, canonical auth and the account pool, runner validation, wrapper bakery, startup sync, skills and AGENTS and client config, quota, inference gateways, engine master switch, insecure windows, agent messaging, calls and conferences, wake/cron, watchdog, reboot handoff, host daemon and spawn, operator portal and Android companion, session housekeeping, MCP (projects, secrets, shared memory, Git Director, transfers), and the API process shutdown hook.

`cxx` surfaces: persona dispatch, `native` / `native-entry`, launch and resume, sync, doctor and status, update and uninstall and cron, portal, agent messaging and calls, daemon, reboot, watchdog, housekeeping, `grok-auth`, Claude quota statusline, and `cxx remote`.

Engine deltas that are intentional, and not bugs: Codex lane and wholesale `config.toml`; Claude collections and `settings.json` deep-merge; Grok subscription OIDC with one refresher, on-disk skills, and no CLI quota enforcement.

## Confirmed

These were re-read in the tree. Line numbers are from that read.

### Native SIGINT and SIGTERM become an immediate SIGKILL

Codex, Claude, and Grok all start the native CLI with `exec.CommandContext` on a context cancelled by `signal.NotifyContext` for SIGINT and SIGTERM (`wrappers/cxx/internal/app/codex/main.go` around 398, `internal/app/claude/main.go` around 323, `internal/app/grok/main.go` around 198 and `execute` around 787). Go 1.25 (`wrappers/cxx/go.mod`) kills that child with `Process.Kill` as soon as the context cancels. `WaitDelay` is not set.

Codex and Claude also forward SIGINT, SIGTERM, and SIGHUP (`internal/codex/exec.go` around 301, `internal/claude/exec.go` around 280). The comment on `RunCapture` says signals are forwarded. The forward and the SIGKILL are the same signal, so a native graceful handler does not get time to finish. SIGHUP is forwarded and does not cancel that context, so SIGHUP is the one graceful path on Codex and Claude.

Grok does not forward SIGINT, SIGTERM, or SIGHUP. SIGINT and SIGTERM SIGKILL the native CLI and the private leader. SIGHUP is not caught, so the process dies by the default disposition and `Runtime.Close` does not run.

### Grok SIGKILL and SIGHUP leave the private runtime directory

`Runtime.Close` (`wrappers/cxx/internal/grok/runtime.go` around 619) is the only remover of the per-launch directory under the Grok state `runtimes/` tree, including `auth.json`. It is deferred from `internal/app/grok/main.go` around 592. SIGKILL skips it. Nothing else reaps those directories. `cgx login` has the same shape: `os.RemoveAll` on the throwaway home is a `defer` in `internal/app/grok/login.go` around 124, so a kill during login can leave a second copy of the refresh token. The session flock is released by the kernel; the files are not.

### `cgx login` does not force `grok login --device-auth`

`docs/interface-cgx.md` says `cgx login` and the admin seed command both run `grok login --device-auth` in a throwaway home, because a login may have only one refresher. The seed script does pass `--device-auth` (`api/src/services/install-token.ts` around 232). `cgx login` runs `login` plus the caller's args (`internal/app/grok/login.go` around 150) and does not add `--device-auth`.

### `cxx remote` is a stub, and the fleet tells agents to use it

Every local verb in `wrappers/cxx/internal/remote/command.go` (`info`, `exec`, `read`, `write`, `wait`, `signal`, `ps`, `rm`, `get`, `put`, `push`, `pull`, `down`, and the on-target verbs) returns `E_NOT_IMPLEMENTED` after parsing flags. Tests expect that. `docs/OVERVIEW.md` describes cursors, reconnect, and a binary that installs itself on the target. `REMOTE_EXEC_GUIDANCE` in `api/src/services/remote-exec.ts` tells agents to run those commands and never to re-run a job. The server side of this feature is the on/off switch and that guidance. This is the same binary for all three engines.

### Transfer chunk append is not crash-safe

`api/src/services/agent-transfers.ts` `appendChunk` writes the bytes with `appendFile` (around 629) and only then updates `sizeBytes` (around 641). A crash in between leaves a file longer than the row. The next resume checks `offset` against the old size and appends a second copy. The final hash is of the whole file. Same store for every engine.

### `expected_sha256` on shared memory is check-then-act

`api/src/services/shared-memories.ts` `writeOnce` compares `expected_sha256` (around 432) and then `persist`s. That check is not inside a transaction and is not repeated under `SELECT ... FOR UPDATE`. Append takes that lock. Two replaces that both read the same digest can both commit. Same store for every engine.

### CLI approve of a new host assigns Codex while the fleet switch is off

`docs/interface-api.md` lists `/cli/auth/approve` among the actions that must not newly assign a switched-off engine, and says omitted engines fall back to the default set minus switched-off ones. `api/src/services/cli-auth.ts` `approve` calls `registerOrRotate` with no `engines` (around 146). `api/src/services/host-registration.ts` runs `assertEnginesAddable` only when `engines` was passed (around 59) and stores `'codex'` for a new host when the field is omitted (around 117). An existing host keeps its current assignment, which matches the doc. A new host does not.

### Locking an AGENTS document does not check that document's engine

`agents_documents.engine` exists (`api/src/db/schema.ts`). `AgentsService.setServeMode` loads the row by id only (`api/src/services/agents.ts` around 373) and then stores that id as the locked document for the request's engine. A Codex lock can point at a Claude document.

### A non-boolean `stream` flag bypasses the Grok refusal

`assertBackendRequestControls` (`api/src/services/gateway-backends.ts` around 310) treats `stream` as set only when it is boolean `true`. The OpenAI-compatible route then does `if (payload.stream)` (`api/src/routes/v1/index.ts` around 143) and synthesizes an SSE body from the finished CLI result. `stream: 1` therefore runs the Grok CLI and is still returned as a stream. Boolean `true` is refused before exec.

### Codex concurrent sync publishes `AGENTS.md` and `config.toml` through one shared temp name

`atomicWrite` in `wrappers/cxx/internal/persona/codex/lifecycle/run.go` (around 1631) writes `path + ".new"` and renames it. There is no unique temp name and no fsync. `--allow-concurrent-sync` is the path that writes without `cdx.lock`. Two such writers share `.new`. A kill after the truncate and before the rename lets the other writer publish a short file.

### Git Director expires a live registration, and `git_register` does not bind the caller

`sweepExpired` in `api/src/services/git-director.ts` says a bound live agent must not be evicted for silence (around 360). The `timedOut` filter under that comment still includes every non-abandoned row whose `expiresAt` has passed, including a row whose address is not in the dead set. A heartbeating holder is marked `expired` when the registration TTL elapses.

`git_merge_status` runs that sweep and then extends only `leaseExpiresAt` on the merge request (around 1072). It does not extend `git_worktrees.expiresAt`.

`git_register`'s MCP handler (`api/src/services/mcp-tools.ts` around 1684) forwards the model arguments and the host. It does not fill `engine` from the dispatch engine, even though the client config sends `X-Engine`. Address binding in `git-director.ts` (around 1338) needs that engine. The same handler serves Codex, Claude, and Grok.

### Companion daemon start feeds Grok the prompt on stdin

`wrappers/cxx/internal/agentbus/daemon.go` writes the Grok prompt to a file, appends `--prompt-file` (around 641), and then sets `cmd.Stdin` to that same prompt for every engine (around 645). `worker.go` (around 464) and `reboot.go` (around 514) set `Stdin` to nil for Grok. The native CLI copies wrapper stdin (`internal/app/grok/main.go` around 789). A companion-started Grok session therefore still has the prompt on stdin.

### Documented host pruning never runs

`pruneInactiveHosts` (`api/src/services/host-auth.ts` around 93) is only called from `api/test/unit/services/host-auth.test.ts`. `docs/interface-api.md` still says auth, register, and admin flows delete inactive hosts, never-provisioned hosts older than 30 minutes, and hosts past `expires_at`. Quick-register sets `expires_at` about two hours out (`host-management.ts` around 388) and nothing later reads it. This is fleet-wide, not one engine.

### An installer token is consumed before the script is built

`api/src/routes/install/index.ts` calls `markInstallUsed` (around 94) and only then `buildInstallerScript` (around 107). A thrown build returns `installer_build_failed` and does not release the token. Seed tokens have `releaseSeed`. Install tokens do not. The same redeem path checks that the token's engine is fleet-enabled and does not check that the engine is still assigned. `HostManagementService.setEngines` (around 818) updates `hosts.engines` and does not delete outstanding install tokens, so a removed engine's token can still emit a script for that engine, with the host API key, while the fleet switch remains on.

### Grok maintenance ignores `--allow-concurrent-sync`

The launch and `cgx sync` path passes `o.concurrent` into `syncMeasuredManagedWith` (`internal/app/grok/main.go` around 515). `syncManaged`, which update and cron use, always calls `syncMeasuredManaged` and that always passes `unlocked=false` (around 343 and 352). The flag is parsed for `sync`, `cron`, `status`, and `doctor` (around 131). Maintenance can still tell the operator to pass a flag that this path does not honor. The lifecycle agent's wording that the flag never unlocks sync is broader than the code.
