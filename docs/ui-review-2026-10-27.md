# WebUI visual and usability review — 2026-10-27

Three independent assessment slices reviewed operations, coordination, and
settings/authentication. Findings were checked against `DESIGN.md` in actual
rendered pages before targeted implementation. This is a visual and interaction
review with automated regression evidence, not a claim of complete usability or
WCAG conformance.

## Confirmed findings and fixes

| Surface / reproduced problem | Result | Design rules |
| --- | --- | --- |
| Hosts status filters at 320 px clip and concatenate labels; Accounts engine filters overflow their fixed-height touch container | Hosts use a two-column narrow layout; both containers grow with their controls | VIS-2/3, ACC-3/4 |
| Sidebar and mobile account links remain 36 px on touch; Overview label truncates at 320 px | Shared standalone flex links receive 44 px targets, the tablet rail accommodates them, and the mobile label uses its available width | VIS-1/3, ACC-3/4 |
| Global touch sizing turns switches into circles and enlarges checkbox artwork | Hit areas grow independently of the stable switch track and checkbox mark; keyboard behavior remains native | VIS-1/3, ACC-1/3 |
| Mobile live-update state relies on a colored dot | Paused, disconnected and connecting states have distinct glyphs with the existing accessible explanation | VIS-4, INT-6, ACC-1 |
| Accounts show zero totals while loading or after an initial failure | Counts require an actual response; retained counts identify a failed refresh as stale | INT-6/7 |
| Filtered-empty Hosts tell operators to clear filters without providing a reset | Clear filters resets search/status/attributes while preserving sort and unrelated URL context | INT-1/7 |
| Long host FQDNs are visually truncated with no touch-readable full identity | Host identities wrap within their cell/card | NAV-2, VIS-2, ACC-4 |
| Project claim expiry and due dates split into flex items and appear out of reading order | Date labels and timestamps wrap together as normal inline prose | VIS-2/3, INT-6 |
| Messaging filters initially show raw `all` and `100` without visible meaning | Persistent labels and explicit selected option text explain status, UUID and result limit before opening menus | NAV-2, INT-2, ACC-1 |
| Chat file/photo labels have approximately 27 px hit areas and no visible keyboard focus | Shared button styling, 44 px touch targets and focus-within treatment preserve the native file picker | VIS-1/3, ACC-1/3 |
| Account settings force four equal columns at 320 px, making labels run together; late font loading can crop the selected tab after its initial scroll | One proper tab row scrolls locally with intrinsic label widths and reveals the selected tab after keyboard/hash navigation and font/container resizing; mounted drafts remain intact | NAV-4, VIS-2/3, ACC-3/4 |
| Completed setup labels escape the local step rail and expand the document by over 500 px | Step buttons establish the containing block for their screen-reader-only completion text; the nine-step rail remains locally scrollable | VIS-3, ACC-1/4 |
| A direct manual article starts below roughly 1,700 px of navigation on a phone | Optional mobile browsing uses a keyboard-accessible disclosure; desktop browsing stays visible, with a single search/navigation instance | NAV-2/3, VIS-3, ACC-4 |

No permission, authentication, provider-account ownership, API, schema or native
wrapper contract changes are part of this slice. No design exception was added.

## Rendered assessment coverage

- Operations: Dashboard, Hosts list/detail, Accounts, Engines and Limits;
  24 baseline route captures at 320/390/1440 px, light/dark, fine/coarse pointers,
  plus navigation, long identities, no-match, delayed-load and failure cases.
- Coordination: 19 route/view combinations across Agents chats/graph, Projects
  and its four peer views, Messaging views, Workflow authoring/history/runs,
  Schedules, Git Director and Transfers; 114 baseline captures at 320/390/1440 px
  in both themes, plus populated conversation/upload controls.
- Settings/authentication: 112 baseline captures across 28 route/state
  combinations at 320 px light, 390 px dark and 1440 px both themes. Includes all
  nine setup steps, four account panels, Library/editor/rules, People, API keys,
  Secrets, Settings, Activity, Reports, Manual, sign-in, reset and CLI approval.
  The 28 representative 320 px Axe scans reported no violations.
- The parent inspected production Overview, Agents and Account through the
  existing authenticated BrowserOS session without changing fleet data. Fixture
  captures were used for failure, destructive-control and signed-out states.

The general design suite also covers all 39 route entrypoints plus 11 variants
at 320/390/768/1440/1920 px in both themes, with Axe checks at 320 px and a manual
article sweep. The new setup regression checks document width as well as local
main width: checking only `main` missed the original escaped absolute content.

Assessment images, geometry, test logs and before/after captures are retained in
`.git/ui-review/{operations,coordination,settings}` on the review checkout. These
are local evidence, not a public artifact store. Reproducible assertions live in
`frontend/e2e/admin-visual-{operations,coordination,settings}.spec.ts` and the
expanded shared-control checks in `admin-design.spec.ts`.

## Verification and acceptance limits

Source/build/browser results and deployment evidence are recorded with delivery.
`npm run check` passed with zero Svelte errors/warnings and 999 unit tests. The
standalone production SPA build passed. Initial test runs also identified and
corrected test locators/fixture setup and a real Firefox font-load timing defect.
Final Chromium and cross-browser outcomes are recorded with delivery.

| Final check | Outcome |
| --- | --- |
| `npm run check` | Zero Svelte errors/warnings; 999 unit tests passed |
| `npm run test:e2e` (fresh final build/run) | 392 Chromium cases passed |
| Isolated seven-file Firefox/WebKit selection | 218 cases validated: 217 passed in the full run; the remaining Firefox target-width assertion reported 43.999984 px for a 44 px target. Rounding only this sub-millipixel measurement to three decimals, then rerunning the complete coarse-pointer case in both engines, passed 2/2. No product change was required. |
| Production SPA build, index references, staged diff | Passed; 67 referenced index assets exist; all 243 SPA files are included in the production comparison manifest |

The Fedora host cannot launch the downloaded WebKit because `libicudata.so.74`
is absent. WebKit 26.5 launches in the release-matched official Playwright
1.62.1 Noble image, pinned to
`sha256:c091b21d9fae78c76e85cd4356431e9b018402f172a214fc7d7a5e9a7e29d8ac`.
The [Playwright container guidance](https://playwright.dev/docs/docker) requires
matching the package and image versions. Isolated Firefox/WebKit tests use the
same seven-file selection as `playwright.cross.config.ts`, against the built
SPA on port 4175, without rebuilding or changing system libraries. Only task-owned
fixture/dependency staging is mounted into the temporary rootless container.
Setup edge assertions allow at most one CSS pixel of browser rounding while
requiring the entire label to stay inside the rail (observed Firefox edge:
0.317 px). This does not hide text clipping or the original 574 px document leak.
Backend/Go suites were not rerun for this frontend-only slice; the API image build
performs its own type check and build.

Populated fixtures exercised the repaired states, but generic Schedules,
Transfers, Git and some graph/group views primarily establish orientation and
empty-state rendering. Not every overlay, permission combination or failure
boundary was manually assessed. Automated Axe, browser keyboard checks and
reviewer screenshots do not establish screen-reader task comprehension.

Manual screen-reader review, physical touch/virtual-keyboard behavior, manual
400% browser zoom and 200% text resizing across every changed surface, independent
operator task acceptance, manual cross-browser usability and field Web Vitals
remain unmeasured. Existing automated enlargement checks and browser engines
are narrower evidence. No analytics deployment is included.

## Delivery and rollback

The committed `public/admin` SPA is rebuilt into the API image. Delivery uses the
existing supervised API deployment on `docker01.uggs.io`, without DB/storage or
credential archives and without wrapper publication. The wrapper remains
0.9.138. The previous API image is retained as a rollback tag; deployment result,
new image identity, public health and served asset hashes are verified separately
from source tests. A source rollback reverts this frontend commit and rebuilds
the API; an immediate runtime rollback recreates the API with the retained image.
No persistent application data is deleted by these UI changes.
