# Database Interface (Source of Truth)

Schema DDL is defined in the Drizzle schema at `api/src/db/schema.ts` (MySQL only). Column names and types below are derived from that schema file.

Operationally, schema changes live as reviewable hand-written SQL in `api/src/db/migrations/` and are applied by the migration runner in `api/src/db/migrator.ts`. It runs automatically at API boot (`RUN_MIGRATIONS_ON_BOOT`, default **on**) and explicitly from `scripts/deploy.sh` between `compose build` and `compose up`; `node dist/migrate.js` (`npm run migrate` in a checkout) drives it by hand, with `--check`, `--list`, `--dry-run`, `--baseline`, and `--reapply`. Applied versions are recorded in `schema_migrations` with the file's sha256, and a `GET_LOCK` advisory lock serialises concurrent runners. Boot fails closed when a migration is pending and `RUN_MIGRATIONS_ON_BOOT` is off. Migrations must be idempotent — `test/integration/db-migrations/migrator.test.ts` re-applies every file against a migrated schema to prove it. See `api/src/db/README.md` for the full contract. **Do not use `pnpm drizzle:push`**: it ignores the migrations folder and reconciles the *entire* hand-maintained `schema.ts` mirror against the live DB, so any pre-existing drift is applied alongside the intended change. It also cannot express FULLTEXT indexes or foreign keys, so it would propose dropping `idx_memories_search`, `idx_coord_project_memories_search`, `idx_shared_memories_search`, and `idx_shared_memory_chunks_search`, and would create the `shared_memory_*` children without their `ON DELETE CASCADE` constraints. `0006_add_shared_memories.sql` back-fills both the indexes and the FKs for exactly that case, but the general warning stands.

- **hosts.browseros_mcp_enabled** — `TINYINT(1) NOT NULL DEFAULT 0`; per-host Codex-only BrowserOS MCP toggle. When enabled, host config baking injects `[mcp_servers.browseros]` pointing to `http://127.0.0.1:9000/mcp` and bumps `hosts.config_version`.
- **hosts.wrapper_track** — VESTIGIAL: retained for compatibility, read by nothing that changes behaviour, and **not** a per-host wrapper kill-switch. The value is unvalidated free text (`VARCHAR(16)`, default `v2`; historically `legacy`/`v2`, with `legacy` inert), and outside the Drizzle mirror and its `idx_hosts_wrapper_track` index the only read is a read-only passthrough into the `GET /admin/hosts` list payload. The wrapper v2 routes gate on a configured signing key first (503 `wrapper_v2_unavailable`) and then on the requested engine appearing in `hosts.engines` (403 `engine_disabled`) — see `docs/wrapper-v2-architecture.md`. Do not confuse it with the identically named wrapper track setting config baking surfaces as `track` in the wrapper block: that one is a settings-loader member whose only implementation is the no-op default, so it is always `stable`.
- **auth_payloads** — canonical auth generation history (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `last_refresh` VARCHAR(100) NOT NULL, `sha256` CHAR(64) NOT NULL, `source_host_id` BIGINT UNSIGNED NULL FK → `hosts.id`, `created_at` VARCHAR(100) NOT NULL, `body` LONGTEXT NULL, `verification_state` VARCHAR(16) NOT NULL DEFAULT `pending`, `verification_checked_at` VARCHAR(100) NULL, `verification_reason` VARCHAR(500) NULL, `engine` VARCHAR(16) NOT NULL DEFAULT `codex`, `generation` BIGINT UNSIGNED NULL, `source_kind` VARCHAR(32) NOT NULL DEFAULT `legacy`, `parent_payload_id` BIGINT UNSIGNED NULL, `credential_kind` VARCHAR(32) NULL, `fingerprint_kid` VARCHAR(191) NULL, `access_fingerprint` CHAR(64) NULL, `refresh_fingerprint` CHAR(64) NULL, `pair_fingerprint` CHAR(64) NULL, `credential_issued_at` VARCHAR(100) NULL, `access_expires_at` VARCHAR(100) NULL, `refresh_expires_at` VARCHAR(100) NULL, `superseded_at` VARCHAR(100) NULL, `purge_after` VARCHAR(100) NULL). The current distributable row is selected through `auth_canonical_heads`; `generation` is unique per engine. `body` remains libsodium `secretbox` ciphertext. Credential fingerprints use the encryption keyring only as HMAC key material and never contain plaintext tokens. Runner readbacks with `pending` or `failed` verification may be retained as quarantined history, but never become the head. Current canonical rows have no retention deadline; a row receives `superseded_at` and `purge_after` only when replaced by a verified successor.
- **auth_canonical_heads** — one explicit verified canonical pointer per engine (`engine` VARCHAR(16) PRIMARY KEY, `payload_id` BIGINT UNSIGNED NOT NULL FK → `auth_payloads.id`, `generation` BIGINT UNSIGNED NOT NULL, `updated_at` VARCHAR(100) NOT NULL). Only a candidate that completed positive live runner verification may advance it. Migration `0005_add_auth_generation_ledger.sql` adds the ledger columns/indexes and this table. Boot backfill decrypts existing rows, derives keyed fingerprints/freshness, assigns per-engine generations, marks only historical rows superseded, and records marker `auth_generation_ledger_v1`.
- **auth_payloads canonical resolution** — `last_refresh` remains a VARCHAR for
  compatibility, but the service parses RFC3339 values and orders them by the
  represented instant, then by descending `id` on a tie only as a legacy
  fallback when no explicit head exists. Before a row can be
  selected, the decrypted body must be JSON, its body/row timestamps must name
  the same instant, its SHA-256 must match, its engine must be known, it must
  be within the accepted timestamp window (2000-01-01 through server now plus
  300 seconds), and it must contain a quality-checked credential for the
  engine's native target (`api.openai.com` or `api.anthropic.com`). With no
  explicit head, legacy fallback considers only structurally valid `verified`
  rows. With an explicit head, that exact generation remains authoritative:
  if later verification marks it failed, its bytes are withheld and resolution
  does not resurrect an older verified row. Quarantined `pending`/`failed`
  descendants are available only to verification and administrative
  inspection. Codex bodies are normalized to one native mode
  (`auth_mode=chatgpt` plus `tokens`, or `auth_mode=apikey` plus top-level
  `OPENAI_API_KEY`) before live verification. Legacy/non-native or
  partial/stale-fingerprint rows are not distributable; the worker verifies the
  exact current projection and advances the head only with a freshly
  fingerprinted verified replacement. Canonical bodies and `auth_entries`
  retain only the selected engine-native target; arbitrary extra targets are
  stripped before runner verification and persistence.
- **auth_entries** — the selected engine-native token mirrored for each payload (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `payload_id` BIGINT UNSIGNED NOT NULL FK → `auth_payloads.id`, `target` VARCHAR(255) NOT NULL, `token` TEXT NOT NULL, `token_type` VARCHAR(32) DEFAULT `bearer`, `organization` VARCHAR(255) NULL, `project` VARCHAR(255) NULL, `api_base` VARCHAR(255) NULL, `meta` JSON NULL, `created_at` VARCHAR(100) NOT NULL); index: `idx_entries_payload` on (`payload_id`); unique key `uniq_entry_target` on (`payload_id`, `target`). New writes contain exactly one target, `api.openai.com` for Codex or `api.anthropic.com` for Claude; legacy history may contain more. `token` uses the same `sbox:v1`/`kid` format as payload bodies.
- **skills** — canonical Skill manifests (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `slug` VARCHAR(255) UNIQUE, `sha256` CHAR(64) NOT NULL, `display_name` VARCHAR(255) NULL, `description` TEXT NULL, `manifest` LONGTEXT NOT NULL, `source_host_id` BIGINT UNSIGNED NULL FK → `hosts.id`, `source_type` VARCHAR(64) NULL, `source_repository` VARCHAR(512) NULL, `source_path` VARCHAR(512) NULL, `source_revision` CHAR(40) NULL, `source_license` VARCHAR(64) NULL, `bundle_sha256` CHAR(64) NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL, `deleted_at` VARCHAR(100) NULL, `engine` VARCHAR(16) NULL); indexes: `idx_skills_updated_at` on (`updated_at`), `idx_skills_engine` on (`engine`). `description` stores the short human/AI summary used in admin/API Skill listings; served agent documents contain only a generic engine-appropriate discovery hint, never these per-Skill descriptions. A non-blank `source_type` is the ownership marker: ordinary store/delete paths treat the row as read-only, while `source_repository`, `source_path`, immutable `source_revision`, and `source_license` provide attribution. `sha256` remains the `manifest` digest; `bundle_sha256` fingerprints the manifest plus every auxiliary file. Matt Pocock imports use `source_type = github:mattpocock/skills`, `source_license = MIT`, and soft deletion when the source is disabled so the cached last-known-good row remains recoverable.
- **skill_files** — auxiliary files for directory-backed Skill bundles (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `skill_id` BIGINT UNSIGNED NOT NULL FK → `skills.id` ON DELETE CASCADE, `path` VARCHAR(512) NOT NULL, `sha256` CHAR(64) NOT NULL, `content` LONGTEXT NOT NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL); unique key `uq_skill_files_skill_path` on (`skill_id`, `path`); index `idx_skill_files_skill` on (`skill_id`). Locally authored manifest-only skills have no rows. External adapters replace the complete validated file set in the same transaction as the parent manifest, and the Matt Pocock adapter includes the root MIT notice in every bundle at `LICENSE.mattpocock`. Disabled-source rows/files remain cached server-side but are excluded through the soft-deleted parent. DDL source: `api/src/db/migrations/0007_add_skill_provenance.sql` (idempotent columns/table plus the cascade FK backfill Drizzle cannot express).
- **secrets** — fleet credential store for the *working* credentials agents use once they are running: GitHub PATs, database passwords, Bookstack/Checkmk tokens, SSH keys, third-party API keys for MCP servers and services (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `slug` VARCHAR(96) NOT NULL, `name` VARCHAR(255) NOT NULL, `description` TEXT NULL, `value_enc` LONGTEXT NOT NULL, `engine` VARCHAR(16) NULL, `source_host_id` BIGINT UNSIGNED NULL FK → `hosts.id` ON DELETE SET NULL, `source_engine` VARCHAR(16) NULL, `tags` JSON NULL, `tags_text` TEXT NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL, `last_rotated_at` VARCHAR(100) NULL, `deleted_at` VARCHAR(100) NULL); unique key `uniq_secrets_slug` on (`slug`); indexes: `idx_secrets_engine` on (`engine`), `idx_secrets_updated_at` on (`updated_at`), `idx_secrets_deleted_at` on (`deleted_at`), `idx_secrets_source_host` on (`source_host_id`). This is deliberately **not** engine-boot auth: `auth_payloads` and `openai_api_keys` hold the login material that gets an agent *started*, behind a live runner-verification gate, and the two are never merged. `value_enc` is the only copy of the value and always holds an `sbox:v1:` envelope — there is no plaintext column, and no `value_sha256`, because a digest of a human-chosen password is offline-crackable and would hand a dump attacker what the envelope exists to deny them; whether an update changed the value is answered by decrypt-and-compare, which advances `last_rotated_at`. `engine` is nullable and null means every engine, matching `skills.engine`. Delivery is MCP-only (`secret_list`, `secret_search`, `secret_get`) and the orchestrator never writes plaintext to a host filesystem. A task can render a retrieved value into its requested destination, so revocation via `deleted_at` prevents future reads but does not remove a task-created copy; every read is audited to `mcp_access_logs` with method `secret.read`, which is why `slug` is capped at 96 rather than 160 — the audit row writes `secret_get:<slug>` into a VARCHAR(128) column. The collation is `utf8mb4_unicode_ci`, so the unique key is case-insensitive; the service lower-cases every slug on write so lookup and constraint agree. `source_host_id` is ownership, not a read filter: the host that created a secret over MCP is the only one allowed to rotate or delete it through `secret_store` / `secret_delete`, and a NULL owner marks an operator-created row that stays read-only to every host — which is what stops a shared infrastructure credential from being repointed by whichever agent guesses its slug. `source_engine` is provenance only. The FK is ON DELETE SET NULL rather than CASCADE so de-registering a host does not destroy the credentials it created; the row survives and becomes operator-owned. Gated by the `secrets_module_enabled` key in `versions`. DDL source: `api/src/db/migrations/0010_add_secrets.sql` plus `0013_add_secret_provenance.sql` (idempotent columns/index plus the FK backfill Drizzle cannot express).
- **claude_artifacts** — Claude-Code-native fleet collections, one table discriminated by `kind` (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `kind` VARCHAR(32) NOT NULL (`subagent`|`command`|`output-style`), `slug` VARCHAR(255) NOT NULL, `sha256` CHAR(64) NOT NULL, `display_name` VARCHAR(255) NULL, `description` TEXT NULL, `model` VARCHAR(128) NULL, `frontmatter` JSON NULL, `body` LONGTEXT NOT NULL, `source_host_id` BIGINT UNSIGNED NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL, `deleted_at` VARCHAR(100) NULL, `engine` VARCHAR(16) NULL); unique key `uq_claude_artifacts_kind_slug` on (`kind`, `slug`); indexes: `idx_claude_artifacts_kind` on (`kind`), `idx_claude_artifacts_updated_at` on (`updated_at`), `idx_claude_artifacts_engine` on (`engine`). - **claude_usage_snapshots** — account-level Claude subscription quota readings, PUSHED by the clx wrapper's fleet-owned statusLine command (never fetched by the server) (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `host_id` BIGINT UNSIGNED NULL FK → `hosts.id`, `source` VARCHAR(32) NOT NULL DEFAULT `statusline`, `five_hour_used_percent` INT UNSIGNED NULL, `five_hour_resets_at` VARCHAR(100) NULL, `seven_day_used_percent` INT UNSIGNED NULL, `seven_day_resets_at` VARCHAR(100) NULL, `fetched_at` VARCHAR(100) NOT NULL, `created_at` VARCHAR(100) NOT NULL); indexes: `idx_claude_usage_host` on (`host_id`), `idx_claude_usage_fetched` on (`fetched_at`). DDL source: `api/src/db/migrations/0024_add_claude_usage_snapshots.sql`. Unlike `chatgpt_usage_snapshots`, the orchestrator never holds or calls out with a Claude OAuth token — Anthropic's Consumer ToS prohibits third-party use of a Free/Pro/Max subscription's OAuth token, with public enforcement precedent. Instead Claude Code itself computes its rate-limit windows and hands them to the statusLine command on stdin on every render; the wrapper reports the already-computed 5-hour/7-day percentages up, throttled locally to roughly once per 5 minutes or on change. The column pair names mirror Anthropic's own naming for the two windows, so unlike `chatgpt_usage_snapshots`' primary/secondary there is no positional ambiguity to resolve.
- **git_clones** — one physical git clone on one host, the Git Director's arbitration unit (`id` CHAR(36) PRIMARY KEY, `host_id` BIGINT UNSIGNED NOT NULL, `clone_key` CHAR(64) NOT NULL, `clone_dir` VARCHAR(1024) NOT NULL, `repo_root` VARCHAR(1024) NOT NULL, `remote_url` VARCHAR(1024) NULL, `remote_key` CHAR(64) NULL, `default_branch` VARCHAR(255) NULL, `first_seen_at` VARCHAR(100) NOT NULL, `last_seen_at` VARCHAR(100) NOT NULL, `archived_at` VARCHAR(100) NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL); unique key `uq_git_clones_host_clone` on (`host_id`, `clone_key`); indexes: `idx_git_clones_remote` on (`remote_key`), `idx_git_clones_host` on (`host_id`, `archived_at`, `last_seen_at`). DDL source: `api/src/db/migrations/0025_add_git_director.sql`. `clone_key` is sha256 of the realpath'd `git rev-parse --git-common-dir`, which is what collapses every linked worktree of one checkout onto a single row — the contention the Director exists to arbitrate. `remote_key` is sha256 of the *normalized* remote (scheme, userinfo, trailing `.git` and trailing slash stripped, host lowercased) so `git@host:org/repo.git` and `https://host/org/repo` group together; un-normalized it would silently never group, a failure with no error and no symptom. Grouping by remote is for cross-host visibility only and never widens arbitration: a local merge on one machine must not block another.
- **git_worktrees** — one registered worktree within a clone (`id` CHAR(36) PRIMARY KEY, `clone_id` CHAR(36) NOT NULL, `host_id` BIGINT UNSIGNED NOT NULL, `worktree_path` VARCHAR(1024) NOT NULL, `worktree_hash` CHAR(64) NOT NULL, `username` VARCHAR(255) NOT NULL, `engine` VARCHAR(16) NULL, `agent_bus_address_id` CHAR(36) NULL, `branch` VARCHAR(255) NULL, `head_sha` VARCHAR(64) NULL, `task` TEXT NULL, `declared_paths` JSON NULL, `target_branch` VARCHAR(255) NULL, `status` VARCHAR(16) NOT NULL DEFAULT `active`, `registered_at` VARCHAR(100) NOT NULL, `heartbeat_at` VARCHAR(100) NOT NULL, `expires_at` VARCHAR(100) NOT NULL, `released_at` VARCHAR(100) NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL); unique key `uq_git_worktrees_clone_path` on (`clone_id`, `worktree_hash`); indexes: `idx_git_worktrees_clone` on (`clone_id`, `status`, `expires_at`), `idx_git_worktrees_address` on (`agent_bus_address_id`). The actor identity is the worktree *path*: `POST /mcp` authenticates a host and every agent on that box shares one API key, so the credential cannot distinguish two worktrees. `agent_bus_address_id` is enrichment only — resolved against `agent_bus_addresses` on the same host-and-working-directory digest its `idx_agent_bus_addresses_cwd` index already keys, when Agent Messaging is on, which supplies liveness without inventing a second heartbeat, and left NULL when it is off. `expires_at` is load-bearing rather than hygiene: agents die mid-session constantly, and without a TTL the first crashed one wedges its clone forever. Expiry is swept on read, like the call-PIN sweep in `agent-messaging.ts`, not by cron. `status` runs `active` → `released` (the agent said it was done), `abandoned` (its bound address has no live session, so the fleet knows it ended) or `expired` (it merely stopped calling, the only signal available with Agent Messaging off). Retired rows are kept rather than deleted so a console can still show that somebody was here and when — a registration that silently vanished would read as an empty clone, which is a worse lie than a stale one.
- **git_merge_requests** — a merge request and, once granted, the lease itself (`id` CHAR(36) PRIMARY KEY, `clone_id` CHAR(36) NOT NULL, `worktree_id` CHAR(36) NOT NULL, `client_request_id` VARCHAR(191) NOT NULL, `target_branch` VARCHAR(255) NOT NULL, `base_sha` VARCHAR(64) NULL, `head_sha` VARCHAR(64) NULL, `changed_paths` JSON NULL, `verdict` VARCHAR(16) NOT NULL, `decided_by` VARCHAR(16) NOT NULL, `reason` TEXT NULL, `overlap` JSON NULL, `holder_worktree_id` CHAR(36) NULL, `model` VARCHAR(128) NULL, `lease_expires_at` VARCHAR(100) NULL, `requested_at` VARCHAR(100) NOT NULL, `decided_at` VARCHAR(100) NOT NULL, `renewed_at` VARCHAR(100) NULL, `completed_at` VARCHAR(100) NULL, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL); unique key `uq_git_merge_requests_client` on (`worktree_id`, `client_request_id`); indexes: `idx_git_merge_requests_lease` on (`clone_id`, `target_branch`, `verdict`, `completed_at`), `idx_git_merge_requests_worktree` on (`worktree_id`, `requested_at`), `idx_git_merge_requests_recent` on (`clone_id`, `requested_at`). There is deliberately no separate lease table: the live lease on (`clone_id`, `target_branch`) is the row here with `verdict` = `allow`, `completed_at` NULL and `lease_expires_at` in the future. MySQL has no partial unique index, so exclusivity is held by a `SELECT … FOR UPDATE` on the clone row — this codebase uses row locks everywhere and advisory locks nowhere. `uq_git_merge_requests_client` is the retry guard, the same shape as `uq_agent_bus_messages_sender_client`: MCP calls get retried, and without it a retry mints a second queued row and shows the arbiter a contender that does not exist. `decided_by` separates `policy` (the uncontended fast path, or the fallback when no arbiter is reachable), `llm` (a model judged a real contention) and `operator` (forced from the console), so a verdict that cannot be reproduced is still attributable.

Keys used in code: `client_version` (fleet CLI pin), `client_version_override`, `client_version_enforce_exact`, `client_version_checked_at`, `client_version_lock` (exact Codex CLI pin), `client_version_lock_claude` (Claude equivalent), `client_available` (legacy PHP-era cached Codex client version, still read as a fallback), `github_release_codex-cli` and `github_release_claude-cli` (cached upstream release JSON — GitHub for Codex, npm for Claude Code), `wrapper_version`, `wrapper_sha256`, `wrapper_url` (published wrapper build, written at boot), `runner_state`, `runner_last_ok`, `runner_last_fail`, `runner_last_check`, `quota_hard_fail`, `quota_limit_percent`, `quota_week_partition`, `usage_scaling_rules`, `api_disabled`, `openai_api_disabled`, `claude_api_disabled`, `claude_models_disabled`, `claude_default_model`, `claude_max_tokens`, `auto_update_enabled`, `cdx_silent`, `clx_silent`, `admin_theme`, `reverse_dns_enabled`, `inactivity_window_days`, `insecure_approval_enabled`, `insecure_fleet_window_until` (absolute ISO deadline of the fleet-wide insecure window; present-and-future means open, present-and-past means the close still owes its sweep, absent means closed — an absolute instant rather than a minute count so the per-host 480-minute clamp cannot truncate it), `projects_module_enabled`, `secrets_module_enabled` (fleet secrets store master switch; gates both the `secret_*` MCP tools and the managed AGENTS.md guidance), `project_board_enabled` (project board master switch; gates the board's MCP tools, though `project_board_list` answers a disabled status rather than failing, and never gates `project_todo_*`, which is a view of the same cards and predates it), `git_director_enabled` (Git Director master switch; gates the `git_*` MCP tools and the managed AGENTS.md guidance), `git_director_model` (optional model override for contended merge verdicts), `agent_portal_enabled` (persistent global master switch, seeded `0`), `agent_messaging_enabled` (persistent agent-to-agent master switch, seeded `0`), `skill_source_mattpocock_state` (JSON source switches, immutable/LKG revision, counts, timestamps, status, and error), `agents_backup_limit`, `log_retention_enabled`, `log_retention_days_logs`, `log_retention_days_mcp`, `log_retention_days_events`, `log_retention_days_graph_stats`, and the one-time migration marker `auth_generation_ledger_v1`. The client-version, wrapper and runner families also exist with a `_codex` or `_claude` suffix, which `api/src` appends to the base key rather than spelling out; `test/unit/db/docs-versions-keys-liveness.test.ts` fails when a key named here occurs nowhere under `api/src`.

Encryption: `AUTH_ENCRYPTION_KEY` (single-key mode) is generated into `.env` on first boot if missing. Optional keyring mode uses `AUTH_ENCRYPTION_KEYS` (`kid:base64,...`) plus `AUTH_ENCRYPTION_ACTIVE_KID` (see `api/src/security/keyring.ts`); new writes then include `kid` in the ciphertext prefix while legacy `sbox:v1:{base64}` remains decryptable. `api_key_enc`, `auth_payloads.body`, `auth_entries.token`, `install_tokens.token_enc`, `install_tokens.api_key_enc`, `auth_seed_tokens.token_enc`, `agent_bus_messages.content_enc`, and `agent_bus_messages.last_error_enc` are stored as secretbox ciphertexts via `api/src/security/secret-box.ts`. The one backfill that still runs is gated by a `versions` key: `auth_generation_ledger_v1`, which numbers the auth generation ledger and seeds the canonical heads (`api/src/services/auth-generation-retention.ts`). The PHP-era secretbox and host-API-key backfills were not ported, so nothing re-encrypts rows written before this schema.
