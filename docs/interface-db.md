# Database Interface (Source of Truth)

Schema DDL is defined in the Drizzle schema at `api/src/db/schema.ts` (MySQL only). Column names and types below are derived from that schema file.

Operationally, schema changes are applied by running the reviewable hand-written SQL in `api/src/db/migrations/` directly against the DB before traffic — there is no migration runner (`RUN_MIGRATIONS_ON_BOOT` is parsed in `api/src/env.ts` but read by nothing). **Do not use `pnpm drizzle:push`**: it ignores the migrations folder and reconciles the *entire* hand-maintained `schema.ts` mirror against the live DB, so any pre-existing drift is applied alongside the intended change. It also cannot express FULLTEXT indexes, so it would propose dropping `idx_memories_search` and `idx_coord_project_memories_search`.

- **coord_project_memories** — durable project-scoped memories (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `project_id` BIGINT UNSIGNED NOT NULL FK → `coord_projects.id`, `memory_key` VARCHAR(128) NOT NULL, `content` LONGTEXT NOT NULL, `metadata` JSON NULL, `tags` JSON NULL, `tags_text` TEXT NULL, `source_host_id` BIGINT UNSIGNED NULL FK → `hosts.id`, `created_at` VARCHAR(100) NOT NULL, `updated_at` VARCHAR(100) NOT NULL); unique key `uniq_coord_project_memory_key` on (`project_id`, `memory_key`); indexes: `idx_coord_project_memories_project` on (`project_id`), `idx_coord_project_memories_updated_at` on (`updated_at`), fulltext `idx_coord_project_memories_search` on (`content`, `tags_text`). Unlike `mcp_memories` these are project-scoped, so they are visible from every host; `source_host_id` records which host wrote each row. Rows hard-delete (no `deleted_at`) — `coord_project_events` is the audit trail. The fulltext index is created by `api/src/db/migrations/0003_add_coord_project_memories.sql`, which is the DDL source of truth for this table: Drizzle's mysql-core cannot express FULLTEXT, so `schema.ts` omits it and `searchMemories` degrades to a LIKE scan when it is absent. That migration is idempotent and re-runnable, and also back-fills the index onto a table that already exists without it — which is precisely what `drizzle:push` creates, since it builds the table from the `schema.ts` mirror. No key prefix is reserved — the `^coco` reservation on `mcp_memories` exists to redirect callers *here*. Key uniqueness is case-insensitive (`utf8mb4_unicode_ci`) while the app treats keys as case-sensitive strings; lookup and constraint agree, so behaviour is consistent, but `Deploy` and `deploy` are the same row. Same latent quirk as `mcp_memories`.

- **host_users** — usernames per host for uninstall cleanup (`id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, `host_id` BIGINT UNSIGNED NOT NULL FK → `hosts.id`, `username` VARCHAR(255) NOT NULL, `hostname` VARCHAR(255) NULL, `first_seen` VARCHAR(100) NOT NULL, `last_seen` VARCHAR(100) NOT NULL); unique key `uniq_host_user` on (`host_id`, `username`); index: `idx_host_users_host` on (`host_id`).
- **versions** — key/value version store (`name` VARCHAR(191) PRIMARY KEY, `version` VARCHAR(191) NOT NULL, `updated_at` VARCHAR(100) NOT NULL). Keys used in code include: `client_available` (cached client version from GitHub), `client_version_lock` (fleet Codex CLI pin), `claude_fleet_version` (fleet Claude CLI pin), `claude_version_locked`, `wrapper` (Codex wrapper version), `canonical_payload_id`, `canonical_payload_id_claude`, `runner_state`, `runner_last_ok`, `runner_last_fail`, `runner_last_check`, `runner_boot_id`, `daily_preflight`, `quota_hard_fail`, `quota_limit_percent`, `quota_week_partition`, `api_disabled`, `cdx_silent`, `clx_silent`, `admin_theme`, `reverse_dns_enabled`, `inactivity_window_days`, `insecure_approval_enabled`, `projects_module_enabled`, `admin_ws_connections`, `cdx_model`, `cdx_reasoning_effort`, `agents_backup_limit`, `log_retention_days_graph_stats`, and one-time migration markers `auth_secretbox_migration_v1`, `hosts_api_key_encryption_backfill_v1`, `dashboard_graph_stats_backfill_v1`.

Encryption: `AUTH_ENCRYPTION_KEY` (single-key mode) is generated into `.env` on first boot if missing. Optional keyring mode uses `AUTH_ENCRYPTION_KEYS` (`kid:base64,...`) plus `AUTH_ENCRYPTION_ACTIVE_KID` (see `api/src/security/keyring.ts`); new writes then include `kid` in the ciphertext prefix while legacy `sbox:v1:{base64}` remains decryptable. `api_key_enc`, `auth_payloads.body`, `auth_entries.token`, `install_tokens.token_enc`, `install_tokens.api_key_enc`, and `auth_seed_tokens.token_enc` are stored as secretbox ciphertexts via `api/src/security/secret-box.ts`. One-time backfills are gated by `versions` keys: `auth_secretbox_migration_v1` (`auth_payloads.body`, `auth_entries.token`, `install_tokens.token_enc`/`api_key_enc`) and `hosts_api_key_encryption_backfill_v1` (`hosts.api_key`/`api_key_hash`/`api_key_enc`).
