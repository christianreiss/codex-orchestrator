## Live SPA upgrade

On a private loopback origin, three browser engines loaded the release from `480a20e42` at `/admin/dashboard`. Two Fastify instances served the actual old and new asset trees through the production static registration and response envelope. Switching the origin's upstream to the rebuilt delivery reproduced an operator-visible error in Chromium, Firefox and WebKit. Navigating to Hosts requested its old module `31.DwQYVAzs.js`, which returned 404. Both releases advertised version `0.1.0`. The framework checked the live version and showed “Page unavailable”. Clicking Retry fetched a new document and recovered Hosts in all three browsers. In a controlled Chromium comparison, changing only the served release identifier caused the same old tab to reload the target document automatically and show Hosts. The HTTP API for session and business data was a fixture.

Repeated the same actual upgrade after the build started using its source digest. In Chromium, Firefox and WebKit the old chunk again returned 404. Each browser fetched the new version and then exactly one fresh `/admin/hosts` document. Hosts appeared automatically without a Retry action. A separate Python implementation hashed all 702 sorted input paths and their contents and produced the shipped identifier `aa709239ea8c17fa535e75ca58a1158e1f07a23691e0db700e0b7cfc1b5d295d`. The build-version unit contract also passed.

In a separate run, the operator entered a workflow title before the switch. Declining the browser's discard confirmation kept the open editor and text. Accepting the confirmation discarded the draft as requested. A browser Back after the manual retry reopened an empty editor. The draft check demonstrates the existing navigation guard and its boundary.
