# Product function and reachability matrix

The family rows trace each user goal through its public entry, persisted state, consumer and observable outcome. Within each family, the [operation register](orchestrator-entrypoints.tsv) gives the concrete registration, source line, guard and available level of evidence. The [module index](orchestrator-modules.tsv) supplies direct parents, deployment roots and conditional build targets. References to JavaScript imports include type-only dependencies. An indexed edge does not establish that a request executed every branch.

The [complete per-entry matrix](orchestrator-functions.tsv) joins each registration to its family goal, persistence, downstream consumer, feedback, recovery, rights, decision and the evidence for that particular entry. HTTP rows include the observed response classes and any named operator assertions. CLI rows identify entered and shared dispatch branches. Fleet tool rows also carry the verified scenarios and source lines from the [operator, filesystem, schedule and Git run](orchestrator-operator-mcp.tsv). Empty operator cells mean no matching assertion in that harness. Rebuild the export with `python3 docs/reports/orchestrator-function-details.py` after regenerating the source registers.

The [integrated review](orchestrator-review.md), [browser evidence](orchestrator-browser.md), [Android evidence](orchestrator-android.md) and [security and operations evidence](orchestrator-review-security.md) give measured results and outstanding boundaries. Browser registration, fixture browser tasks, real HTTP/MySQL navigation and native provider inference are distinct observations.

## How to inspect an operation

The [HTTP method/path trace](orchestrator-http-trace.md), [HTTP callback evidence](orchestrator-handler-evidence.md), [wrapper dispatch and host MCP checks](orchestrator-client-evidence.md) and [operator MCP exercises](orchestrator-operator-mcp.md) qualify the reachability of individual registrations. Each records the actor, executed boundary and remaining attribution limits.

For an HTTP path, start with the exact method and URI in the operation register. GET and HEAD remain separate. Its source is the Fastify registration. An admin capability is a first gate; callback-specific owner, key, host, engine, project, account and object checks still apply. A capability-free capture row directs the reader to that handler. A successful HTML navigation serves a shell before its JSON session and data checks. The 42 real browser entries include dynamic instances using test records, explicit denied states or missing-resource recovery.

Fleet MCP and the local agent broker keep separate catalogs. Connector MCP has its own restricted OAuth operation set. Tool discovery records the declared shape and dispatch, while actual invocation is separately measured. A case in a Go command parser supplies a local argument under the enclosing switch and build target, so the same word can occur at several depths. The four official personas share the cxx binary; native entry shims also preserve their own command grammar.

The event register has separate rows for the canonical admin WS names, literal publisher sites, SPA query invalidations and SSE response sites. An event may use a dynamic publisher, owner outbox, wildcard/prefix routing or an optimistic client refresh. A literal-reference count is not a subscriber count. Server access to streams is checked at the connecting route. The UI entries include embedded modal roots and both literal and data-driven tab selectors; project IDs, dynamic shell items, search results and conditional tabs are evaluated with the current session. Browser deep links and interaction evidence are supplied separately.

## Reproducibility and boundaries

Run `python3 docs/reports/orchestrator-inventory.py` from the integration checkout after installing the API dependencies and with Node and the wrapper Go toolchain available. The program refreshes the statically derived portions and both inventory counts from Git-visible source and consumes the retained captured HTTP/fleet/local MCP rows. The working tree may include new integration-owned files before staging. Dependency installation trees, review scratch storage and removed source files are excluded. A recapture of HTTP methods and live tool visibility requires an isolated, ready owner and its own MySQL schema. A fresh capture on 2026-11-21 used a separately initialized MySQL schema, storage directory and ephemeral encryption key. It produced 960 Fastify registrations, including a multi-method OPTIONS registration. The capture came from Fastify `onRoute` at startup, with method, URL, originating registrar, prehandlers, `guardForRoute` and owner-response metadata. Fleet MCP used `tools/list`. Local MCP used the Go compatibility fixture; it replaces a connected session broker. Optional engine and capability views can hide operations.

For HTTP recapture, start an isolated MySQL schema as described under `api/test/fixtures`, then run the following from `api/` with its `TEST_DATABASE_URL`, `DATA_ROOT` and `ENCRYPTION_ACTIVE_KEY` already set. The program boots the real owner, collects route registrations before listening and closes it. Repeat with `ADMIN_WS_ENABLED=0` to check the conditional surface. The default-off capture yielded 961 method/path pairs. With the switch enabled the same build registered 963: exactly GET and HEAD for `/admin/ws` were added.

```sh
route_capture=$(mktemp)

cd ..
python3 docs/reports/orchestrator-inventory.py --routes "$route_capture"
rm "$route_capture"
```

The [handler evidence](orchestrator-handler-evidence.md) uses V8 function counters to distinguish executing a callback from registering a route. It also identifies shared handlers, internal function counters and generated HEAD methods.

The static graph starts from SvelteKit filesystem routes, API/runner/worker/operator entries, Android manifest declarations and the KDE package. Local module imports, CSS imports, named Kotlin declarations and QML object names identify the direct parent in the module index. Kotlin symbol references are static candidates: compiler overload selection, reflection, generated Android resources and dynamic service discovery need separate runtime evidence. The five Go package dependency lists come from the release targets in `wrappers/Makefile`. A sixth list uses the Linux tracing build tag. Windows-only source is outside this release set. Fixtures, historical SQL migrations, generated SPA bundles, bundled third-party assets and build tooling remain separately classified.

Knip intentionally excludes the UI primitive tree and considers API tests as entrypoints. A green Knip check would therefore have missed a test-only registration service and an unused primitive. The last caller of `createHostRegistrationService` disappeared with `38b5098a1`. Its successor is the public admin registration service and stageable owner operation. Rotation, encrypted credentials, emitted events, engine suspension, insecure windows and MCP token revocation now run against this active path. The two old separator files had no import, re-export, barrel registration or data-driven component lookup outside their own directory. They entered with the SvelteKit scaffold `b09a726bf`; Bits-UI menu separators remain independent. The API and frontend npm packages are private. Neither removal requires a migration or a native client update.

The source-level inventory also keeps signing and retention CLI entrypoints, model/schema generators, project portal components still reachable from integrated chat, wrapper aliases, optional tracing, the Android manifest's exported components, Caddy's selectable TLS fragments, Plasma's package loader and historical migrations. See each component README or the authoritative interface contracts for the full wire grammar.

The inventory generator accepts a runtime Fastify `--routes` capture and a two-identity `--fleet-tools` capture.
