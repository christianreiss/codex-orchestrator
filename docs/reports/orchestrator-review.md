## System map and working boundaries

The baseline contains 3,882 tracked files. The first-party surfaces include the
Fastify API, the four native launchers in one Go executable, the Svelte SPA,
Python inference runner, Android companion, Plasma widget, Advisor, media and
design-review workers, installers and deployment tooling. The API also owns
the external-client host and two independent authentication domains for admin
and managed hosts. An engine assignment, a gateway key namespace and the
actual provider backend are distinct inputs to request handling.

## What changed for operators and clients

| User task | Product decision | Observable result |
| --- | --- | --- |
| Start or recover an installation | Keep the one-owner model. Add a durable fresh-schema checkpoint and controlled recovery for previously attached generations. | Interrupted baseline installation resumes at a proven statement. Subsequent restarts preserve that deadline. |
| Maintain four different native clients | Keep the engine-specific account, config and tool contracts. Repair implicit downgrade and stale status messages, and project telemetry the native client actually emitted. | A configured Kimi pin takes effect and clears again. | Let connectors delegate agent work | Repair the existing OAuth connector tool and use the same durable work queue as a managed request. | A retry with the original ID returns its existing message. The caller can read its recorded result after reconnect. |
| Edit files and workflows in the console | Add an optional metadata-only file listing to the current endpoint. Preserve file bytes, open drafts and authenticated browser state through ordinary retries. | The operator opens the selected file on demand and can change binary descriptions. An open tab recovers across a release. User and role changes discard data that belonged to the prior identity. |
| Use the phone or desktop companion | Keep the shared pairing flow. Improve Android large-text and keyboard behavior. | Coordinate large Git changes | Preserve the full merge scope when a diff reaches 500 distinct paths. Waiting, status polling, retry identity and legacy receipt checks exercised the same complete scope. |
| Unblock setup after repairing infrastructure | Add **Check again** to the first-run infrastructure step before the owner exists. Keep the last response readable through a failed recheck. | A real browser saw five passing checks, stayed on the same page during a wrapper repair, issued one additional GET on Enter, saw six checks pass and opened the owner step. |
| Monitor readiness | Evaluate the six critical requirements using one wrapper registry per public route. Keep the setup checklist available through the authenticated wizard once an owner exists. | Unchanged artifacts reuse their digests. Atomic replacement with an unchanged timestamp triggers a new verification. Public probes avoid the four account checks and host inventory. |
| Operate and clean up the installation | Remove the automatic dump and env copy, orphaned host service, unused UI components and stale build rules. Consolidate duplicate document checks and wrapper dispatch. | Existing compatible URLs, single-owner drain and the signed update bridge retain their current consumers. The changes and removal evidence appear under AC-001, AR-001/002, CLN-001–004 and WR-004/005. |

The existing command palette, Doctor, Supervisor, Workflows, Feedback, Transfers and Secrets keep their original entry points. The review added recovery, diagnostics and file-list capabilities to the existing product. Kimi's prompt and Stop hooks now keep the registered receiver available through later explicit listens even with the portal switched off. Per-function decisions and the execution boundary for each entry appear in the [matrix](orchestrator-functional-matrix.md).

A missing original transcript can now be replaced only through a session-gated admin action or the existing MCP operator credential paired with the host credential. The earlier implementation exposed the approval tool to all authenticated hosts. On the corrected API, ordinary host discovery and dispatch denied the operation, SQL showed an unchanged delivery with zero grants, and two operator approvals produced one auditable grant.
