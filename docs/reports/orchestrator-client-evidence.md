## CLI and local MCP dispatch

The [dispatch table](orchestrator-client-evidence.tsv) identifies all 409 indexed CLI option/case sites and all 83 tools registered in the wrapper's local MCP bridge. A positive single-label counter places execution inside that case. A positive multi-label counter establishes that a member of that case was used. It does not identify the alias or establish successful provider or external service behavior. A zero identifies an unentered Go basic block in the named run. Native children launched as ordinary external Go binaries have separate counters.

At 0.9.200, the isolated normal Go profile with the native opt-ins recorded 6,234 test and subtest passes across 86 passing packages and seven skips. The Go suite entered 67 single-label CLI cases and 209 shared cases. Instrumented invocations entered 89 single-label cases and 170 shared cases. The union covers 378 of the 409 indexed CLI cases. 31 cases have no direct counter in either run. All 83 local MCP registration cases have unit evidence, including 57 grouped cases. Each per-operation row identifies a specific or shared dispatch case and the execution boundary.

The second profile used a separate coverage build of the real multicall executable. Its [offline check](orchestrator-wrapper-smoke.sh) ran in an unprivileged Linux container without a network, with a private HOME, disposable working directory, read-only root and a writable coverage mount. It checked exit semantics at the normal CLI for help, version, per-engine sync, status, doctor, update, native entrypoints, missing configuration and service discovery. Signed installation, live transport and actual native writes were checked independently.

The final profile also ran 46 labelled operations on the synthetic signed four-engine host. The [signed-host driver](orchestrator-wrapper-signed-smoke.sh) checks failure diagnostics as well as exit status. These covered real private CLI versions, host and persona cron install/remove, normal maintenance, configured status and doctor output, and native Kimi management requests. Thirty-five commands returned zero. Eleven returned nonzero for unavailable subscription state, a timed-out client preflight, a degraded status or an explicit native-management refusal. The two successful refusal checks apply to native update and upgrade. The current Kimi command grammar has no install or setup subcommand. Their diagnostic invocations ended during preparation, as recorded in the fixture, and supply no successful native-command result. The profile counts code entered on either path; these negative outcomes provide no inference or subscription proof.

To regenerate, run from the repository root with the same Go version. Run `go test -coverprofile=PROFILE ./...` from `wrappers/cxx` with the native opt-ins for the full suite. Build the CLI in that directory with `CGO_ENABLED=0 go build -cover -coverpkg=./... -o BINARY ./cmd/cxx`. Mount that binary at `/review-cxx`, a container-writable empty directory at `/evidence` and the check at `/smoke`. Use a tmpfs for `/work`, no network and a tmpfs or private directory for the synthetic home. Run `sh /smoke`, then `go tool covdata textfmt -i=COUNTER_DIR -o=CLI_PROFILE`. Rebuild the [entry register](orchestrator-entrypoints.tsv) first, then run `python3 docs/reports/orchestrator-client-evidence.py PROFILE OUTPUT CLI_PROFILE` in the checkout root.
