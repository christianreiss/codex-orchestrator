## CLI and local MCP dispatch

The [dispatch table](orchestrator-client-evidence.tsv) identifies all 412 indexed CLI option/case sites and all 83 tools registered in the wrapper's local MCP bridge. A positive single-label counter places execution inside that case. A positive multi-label counter establishes that a member of that case was used. It does not identify the alias or establish successful provider or external service behavior. A zero identifies an unentered Go basic block in the named run. Native children launched as ordinary external Go binaries have separate counters.

With the native opt-ins enabled, Go reported 6,195 test and subtest passes across 85 passing packages and seven skips. The Go suite entered 67 single-label CLI cases and 207 shared cases. Instrumented invocations entered 77 single-label cases and 171 shared cases. The union covers 369 of the 412 indexed CLI cases. 43 cases have no direct counter in either run. All 83 local MCP registration cases have unit evidence, including 57 grouped cases. Each per-operation row identifies a specific or shared dispatch case and the execution boundary.

The second profile used a separate coverage build of the real multicall executable. Its [71-command check](orchestrator-wrapper-smoke.sh) ran in an unprivileged Linux container without a network, with a private HOME, disposable working directory, read-only root and a writable coverage mount. It checked exit semantics at the normal CLI for help, version, per-engine sync, status, doctor, update, native entrypoints, missing configuration and service discovery. Signed installation, live transport and actual native writes were checked independently.

The final profile also ran 46 labelled operations on the synthetic signed four-engine host. These covered real private CLI versions, host and persona cron install/remove, normal maintenance, configured status and doctor output, and native Kimi management requests. Thirty-five commands returned zero. Eleven returned nonzero for unavailable subscription state, a timed-out client preflight, a degraded status or an explicit native-management refusal. The two successful refusal checks apply to native update and upgrade. The current Kimi command grammar has no install or setup subcommand. Their diagnostic invocations ended during preparation, as recorded in the fixture, and supply no successful native-command result. The profile counts code entered on either path; these negative outcomes provide no inference or subscription proof.
