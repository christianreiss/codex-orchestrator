## Coverage and compatibility

Across the [host round trips](orchestrator-mcp-receipts.tsv), the [operator round trips](orchestrator-operator-mcp.tsv) and these 19 new receipts, all 107 registered Fleet MCP tool names have a named success result. The previous 68 and 23 unique names overlapped in three places, yielding 88 before this run. A separate 20:34:39–20:35:39 UTC run of the same revision compared actual host and operator discovery with Feedback, Roles, Slop and the filesystem root enabled. The host saw 100 names and the operator saw all 107. The seven additional names were the six filesystem tools and the fresh-start approval. The 19 positive receipts reproduced byte for byte. Connector MCP has its own namespace. A named receipt covers the listed identity, task and observed outcome. Different engine sessions, error contracts, external provider work and every optional argument have separate evidence requirements.

The 5b95933 revision limits replacement approval to the MCP operator capability. Ordinary host credentials and native bridges lose access to this administrative operation. Existing operators can use the authenticated web delivery log or present the configured operator bearer alongside the host credential. Historical grants and the one-time consumption rules retain their semantics. The HTTP discovery and dispatch checks failed on the previous revision and pass on the fixed version. The focused MCP, manual catalogue and managed-document tests passed 219 of 219. [JSON-RPC boundary tests](../../api/test/integration/mcp/jsonrpc.test.ts)

## Reproduce

Use an exclusive disposable MySQL 8.4 instance on loopback. Install the locked dependencies in `api/` and `slop-worker/vendor/slop-detector/`; the detector's development TypeScript compiler is required. Supply `REVIEW_MYSQL_PORT`, `REVIEW_MYSQL_PASSWORD` and, if needed, `REVIEW_MYSQL_USER` in the process environment. From the repository root, pass a new output path whose parent exists.

```sh
REVIEW_MCP_COMPLETION=1 node docs/reports/orchestrator-operator-mcp.mjs ./mcp-completion-evidence
```

The operator driver creates new synthetic identities, an owner and a private schema. It calls the additional scenarios before closing its native sessions. The shipped worker watches the run's private filesystem. The compiler writes only into that private root. The existing workflow suite creates its listeners on ephemeral ports and runs in a separate schema. Both schemas are dropped and checked for absence. The successful run keeps the normal operator receipts plus `additional-tools.tsv` with the 19 new receipts and `catalog.json` derived from both real discovery responses. Set `REVIEW_MCP_TRACE=1` to record the two operator API lifetimes with the repository HTTP trace preload in the new output directory. The independent workflow suite emits its own asserted result and runs outside this tracing process.
