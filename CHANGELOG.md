# 2026-10-23

- **Serve hosts, versions and host daemons from RAM.** The API keeps plain reads of these three tables in memory: per-request host authentication, communicator frame admission, kill-switch and engine flags, and daemon settings. That removes about 45 statements per second at idle. It is not a time-based cache. Every write made by the API invalidates the affected rows at once, and a write inside a transaction invalidates again at commit or rollback. Reads inside transactions and locking reads still go to MySQL. Edits from other processes (manual SQL, CLI tools) are detected by a `CHECKSUM TABLE` poll and become visible within `DB_READ_CACHE_RESYNC_SECONDS` (default 15). `DB_READ_CACHE_ENABLED=0` turns the cache off; the API logs hit and miss counters every minute.

- **Index the quota snapshot lookup.** Every `/auth` reads the latest Codex and Claude quota snapshot for one account. Without an account-first index, an account with no snapshots scanned the whole history: 10,000–14,000 rows per call, the largest single MySQL cost at idle. New indexes `idx_chatgpt_usage_account_fetched` and `idx_claude_usage_account_fetched` (migration 0091). Responses are unchanged.

- **Fewer host contact writes.** Session and messaging heartbeats wrote `hosts.last_contact_at` twice per beat. They now write it at most every 30 seconds per host, the same cadence as host authentication. Presence still comes from session heartbeats; `last_contact_at` only feeds display and pruning.

- **Slower idle relay grid.** An idle relay credential re-checks every 10 seconds instead of every 2. New messages, state changes and fleet switches still wake waiting relays immediately. The grid only catches retry, lease and expiry times, which no event announces.

- **Longer empty receiver holds.** The server holds an empty `receiver/claim` for up to 20 seconds instead of 8, and answers at once when a message, portal or fleet-switch event arrives. Existing wrappers allow 35 seconds and keep their 15-second receiver heartbeat between claims.

- **Receiver-bound activity.** An activity report may carry `receiver_bound: true`. It then stays current for as long as the same receiver keeps heartbeating, so the wrapper reports changes only, instead of resending an unchanged state every 15 seconds. Reports without the flag expire as before.

- **Event-driven scope coordination.** Coordination reconciliation now runs about 2 seconds after an event that changes its input (sessions, hosts, settings, engines, claims, projects), plus every 10 seconds for presence and claim deadlines. It used to read a full input snapshot every 2 seconds.

# 2026-10-22

- **Lock-free identity reads.** `agent-messaging/self`, polled by every live receiver every 15 seconds, reads from one read-only snapshot instead of taking the bus-wide enable lock and four row locks. Answers and errors are unchanged.

- **Quiet scheduler ticks.** The Chatty scheduler (every second) and the schedule worker (every 10 seconds) first check with one plain read whether any run is queued, running or waiting, or whether any schedule is due or has an active run. Idle ticks no longer upsert the scheduler lock row or open a locked transaction per schedule.

- **Hold empty receiver claims.** Each live session's automatic receiver polled `receiver/claim` about once a second, nearly always for nothing. The server now holds an empty claim for up to 8 seconds and answers again as soon as a message, portal or fleet-switch event arrives, so idle sessions make roughly one claim every nine seconds without slower delivery. Existing wrappers need no update.

- **One-statement session schedule policy.** The schedule-policy poll each live session sends every 5 seconds reads credential, binding, host, flags, governing schedule, open prompt and active run in one statement instead of six to seven. Outcomes and response shapes are unchanged.

- **One-statement idle relay checks.** An idle relay poll is certified from one consistent read (relay credential, host, daemon gate, fleet flags, candidate addresses, daemon sessions and pending work) instead of four to five queries. Any uncertain, invalid or non-empty case keeps the existing path, errors and locked claim. Bridge and relay authentication read the Agent Messaging enable flag in the same statement as the credential. New indexes: `idx_agent_bus_addresses_relay` and the long-declared `idx_scope_member_session` (migration 0090).

- **Avoid blocked FIFO relay transactions.** Idle relay peeks use the claim's strict ordering predicate, so accepted work and delayed queue heads do not repeatedly trigger locked empty claims. Expiry and routine cleanup remain eligible.

- **Bound relay recovery checks.** Identify digest-recovery targets together before taking address locks. Relays with many dormant addresses no longer issue a recovery query for every unrelated address; selected targets are still rechecked under lock.

- **Unblock dormant relay mail behind digests.** Relays restore certainly unpresented digest members to their original FIFO positions instead of repeatedly scanning an undeliverable digest head. The root remains as a tombstone; leased, accepted, presented or ambiguous groups and newly rebound live sessions are preserved.

- **Avoid relay retry spin.** Ordinary future retries and already accepted work no longer force an idle relay into a locked claim transaction. Expiry, lease replay/requeue and routine/presence-notice cleanup retain the existing locked path.

- **One fresh communicator admission read.** Each frame reads its host, API kill switch and inherited reverse-DNS policy together. Compiled SQL plans reuse construction only; credentials and permissions are read again for every frame, with locked checkpoint revalidation retained.

- **Bound coordination snapshot scans.** Active membership IDs are selected as a set rather than rescanning all membership rows for each historical session. Ended sessions with active membership remain visible for cleanup.

- **Shared relay idle checks.** Parallel long polls for the same credential share only an in-flight empty-queue check on a common two-second timer. Every new request authenticates independently; nonempty queues still use separate fenced claims and retain all execution slots.

- **Skip unchanged coordination sweeps.** Background reconciliation observes its relevant inputs in one fresh database snapshot and skips the locked transaction while they are unchanged. Presence and claim deadlines, title/binding changes and undispatched events still trigger reconciliation. The remembered input comes only from a successfully committed reconciliation snapshot.

- **Keep fleet scans out of successful requests.** Host cleanup runs in the existing retention worker and explicit registration/admin passes, instead of scanning every host after each authenticated response. Expired credentials still reject immediately.

- **Event-driven daemon offers.** Committed starts and resumptions wake the connected daemon immediately. Empty fallback checks run every 15 seconds and read only the operations queue; host authentication and locked admission still run before offering actual work. The existing heartbeat and expiry sweep retain their cadence.

- **Less native-control heartbeat locking.** Valid idle polls use a fresh binding snapshot and checkpoint readiness every seven seconds instead of writing on every three-second poll. Stop requests and reports retain the existing locked path and the 15-second availability window.

- **Cheaper idle receivers.** Peer and portal receivers certify valid empty polls in one fresh database snapshot without opening a transaction. SQL plans are reused without caching permissions or queue results. Coordination batches scope/binding reads per reconciliation, and host authentication reuses its current request's admission row for optional contact bookkeeping.

- **Less idle persistence.** Permanent hosts checkpoint contact at most once per 30 seconds while still checking current credentials/status on every contact; temporary-host expiry renewal is unchanged. Daemon retention scrubs eligible operations in batches and stops issuing repeated zero-row retirement writes for old tombstones.

- **Relay polling CPU hotfix.** Idle relay long polls wait for message events with a two-second reconciliation fallback instead of rebuilding and executing the full claim query chain every 400 ms. Every retry still checks credentials, host/engine admission and delivery fences; host, daemon and address heartbeat events do not wake the loop.

Only a definitive non-active answer stops renewal.

- **Advisors outside scope coordination.** Fleet Advisor sessions get no `scope_context`, `agent_context_get` reports `enabled:false` (`internal_host`), and claim attempts return `agent_coordination_not_applicable` instead of "Target host not found"; advisors fetch transfers into unique files without a claim.
